# StageB 重构复盘（A / B / B+）

## 1) 问题复盘
- 旧 `B` 在 `1e16/3e16/6e16` 上每个预算只有 6 个点，且 `N_non_emb` 区间非常窄（大约只覆盖 `A` 的 1.5%~2.2% 宽度）。
- 结果是：虽然局部 loss 有微小提升，但对 `N_opt(C)` 的全局趋势没有提供稳定信息，反而更容易被局部噪声主导。
- `B+` 修复了 `6e15/1e16`，但它和旧 `B` 分离成两套目录与策略，分析入口不统一，容易出现“部分预算更新、部分预算沿用旧窗口”的混合偏差。

## 2) A / B / B+ 经验总结
- `A` 的价值：提供宽范围、低偏置的首次定位，能看到浅 U 型谷底和多个候选区域。
- 旧 `B` 的问题：`top-1` 锚点 + `0.9/1.0/1.1` 的超窄缩放 + 单层附近扫描，导致“过拟合锚点附近”。
- `B+` 的价值：证明在 `6e15/1e16` 上需要专门加低 N 补点，且要适度放宽层数/LR。
- 关键经验：
  - 局部精修必须保留“左右两侧验证点”，否则会把局部随机最优误判为全局最优。
  - 预算越大，越不能只围绕一个极窄窗口扫描；至少要覆盖“旧最优附近 + 单调增长假设区间”。
  - Stage-B 的目标是“降低不确定性”，不是“只在一个点附近重复采样”。

## 3) 新的统一 StageB 设计原则
- 合并旧 `B` 与 `B+`：统一为一套 `stageB`，覆盖 `6e15/1e16/3e16/6e16`。
- 每个预算都包含：
  - 主扫描块：围绕当前中心点做结构化精修（层数 + N + LR）。
  - 侧向验证：避免只在谷底附近过密采样导致偏置。
- 控制总 FLOPs：避免再次出现“大量算力换来极小信息增量”。

## 4) 新 StageB 扫描配置
- `6e15`：10 runs，`N_non_emb=[1,663,488, 2,230,272]`
- `1e16`：14 runs，`N_non_emb=[3,840,000, 5,598,720]`
- `3e16`：12 runs，`N_non_emb=[4,062,720, 7,526,400]`
- `6e16`：12 runs，`N_non_emb=[4,800,000, 11,089,920]`
- 总计：`48` runs，估算 FLOPs `1.280e+18`

## 5) 与旧方案的区别
- 不再分裂为 `B` 和 `B+` 两条线，避免目录和策略分叉。
- 不再使用“每预算固定 6 点超窄窗口”的旧 `B` 做法。
- 保留 B+ 的低 N 修复经验，但合入统一 StageB，不再单独维护 `stageB_plus`。
